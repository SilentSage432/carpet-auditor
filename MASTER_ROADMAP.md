This result applies to Shift Briefing only and does not transfer to any other Gemini capability. **AI-REDUCE-002 (Deterministic Catalog Taxonomy) — IMPLEMENTATION ACCEPTED — CLOSED** (2026-09-08), the second closed implementation tranche and the first closed **without** a field gate: the only changed surface is the Master-Admin-only taxonomy manager in Settings, and the associate-facing audit drill-down renders byte-identical. Adjacent provenance finding recorded in that plan §5 A1.9: legacy audit `sub_category` values may hold model-authored folder labels; **historical rows are deliberately untouched** because provenance cannot distinguish them safely, and no remediation work item is opened. **AI-RETIRE-001 (Retire Orphaned Snag Triage) — IMPLEMENTATION ACCEPTED — CLOSED** (2026-09-08), the program's first **retirement** rather than reduction: a route, Gemini classifier, deterministic fallback, three-table dispatcher, and an uncalled client helper deleted outright. Orphan status was proved by symbol, URL, field-name, table-name, and prompt-text search — no caller, no UI, no deep link, no cron, no offline replay. It also closed a real exposure GEMINI-001 understated: the route was gated on *any* signed-in actor, so `dispatch: true` could write `downstock_queue`, `rotation_exceptions`, and `shift_walk_tasks` at the lowest auth tier. **No historical rows were touched and no migration was written**, and the route must not be reintroduced behind a stricter gate — the job itself was proven unnecessary. **AI-SAFETY-001 (Bound Gemini Transport Failure) — IMPLEMENTATION ACCEPTED — CLOSED** (2026-09-08), the fourth closed implementation tranche and the program's first pure **resilience** tranche: no capability removed, added, or re-dispositioned. The surviving Gemini surface was confirmed from code as **exactly six consumers** (five API routes plus one Server Action) funnelling through one shared transport, with **no bypass** — `lib/ai/gemini.ts` is the only runtime importer of the SDK. `callGeminiFlash` now runs **one bounded attempt**: a transport-owned `AbortController` with a **20 000 ms** deadline (pinned to the existing `STORE_OPS_FETCH_TIMEOUT_MS`, not an invented number), the timer cleared in `finally` on every exit path, and a single new `GeminiTimeoutError`. **No retry was added, because none existed** — the SDK issues exactly one `fetch` and nothing in the app retries a Gemini call, so "no retry ceiling" meant there was no retry to bound; adding one would have raised paid exposure under a safety label. The SDK's own `timeout` option was deliberately *not* used because it never clears its timer. **No consumer file changed**: prompts, schemas, normalizers, token budgets, persistence, confirmation boundaries, fallbacks, and each consumer's own `isGeminiConfigured()` branch are untouched, and non-2xx / network / malformed / not-configured errors stay byte-identical. One behaviour improves as a consequence rather than an edit — a hung Snap Bay request previously stranded the "Scanning bay…" overlay forever, and now rejects at 20 s into the modal's existing `catch`. **No field acceptance required:** the successful path is unchanged and the failure semantics are fully provable deterministically. **SNAP-DECISION-001 (Snap Bay Repair-or-Retire) — DECISION: RETIRE — COMPLETE** (2026-09-08), and **SNAP-RETIRE-001 — IMPLEMENTATION ACCEPTED — CLOSED** (2026-09-08), the program's **second retirement**, fifth implementation tranche, and fourth closed tranche. The decision was **not** made on the severed lifecycle: it was made because the capability's *intended* job — a Gemini verdict gating `weekly_rotations` completion — conflicts with **Article X** and **Appendix B row B**, so repairing the wiring would have moved it from harmlessly severed to actively unconstitutional. Three further grounds: the source photo was never retained and the repository contains **zero object-storage code**, so the provenance loop could not be repaired in place, only built; **no field-value evidence existed and none could have**, because the row was unreadable and the photo discarded, which is also why INSUFFICIENT EVIDENCE was unavailable — no experiment could decide it without first building the repair; and physical supervisor verification plus the two-stage review/send-back queue already own the completion decision under Art. VI.2. Removed: the route, prompt, response schema, normalizer, local fallback, contracts, persistence helper, client helper, `BayCompleteGatedError`, the modal's persisting branch, Floor's audit plumbing and its **Snap Bay Photo** action, `ZebraChecklist`'s dead audit-gate state and model-verdict override, the FAIL completion gate, the rotation-review join, and the never-rendered supervisor verdict chip and photo. **No substitute was installed** — no stricter role check, no deterministic gate, no repaired rotation binding; the product job itself was rejected, and a contract test blocks a quiet deterministic replacement. It also closed by deletion an actor-scope exposure the decision tranche newly found: the route never called `assertActorCanAccessDepartmentId`, so any signed-in actor could write a row against any department in their store. **`bay_audit_logs` is preserved intact — no migration, no dropped table, no deleted or rewritten rows** — as historical persistence with no runtime owner. **Visual Bay Scan is untouched and deliberately not re-dispositioned:** its route, prompt, schema, token budget, and all three mounts survive, the shared modal is now ephemeral by contract at every mount, and its product value remains **FIELD EVIDENCE NEEDED**. Gemini inventory is now **five consumers — four API routes plus one Server Action**. The Floor drawer opens on **five** shift actions; UX-005C's still-pending Samsung acceptance must be run against it, and no duplicate field gate was created. The durable lesson: **a dead capability can still carry architectural risk when a missing connection would activate an authority path the product should not have** — severance is not safety. **THESIS-001 (Operational Thesis & Rotation-Loop Integrity Audit) — DISCOVERY COMPLETE** (2026-09-08), a read-only trace of the staging → assignment → completion → verification loop that changed no code, and **THESIS-001A (Verification Authority Repair) — IMPLEMENTATION COMPLETE — AWAITING REVIEW** (2026-09-08), which discharged two of its findings. Both leaks were closed by **removing a claim rather than adding a check**. `POST /api/rotations/verify` gated on supervisor authority only when `review_action` was present, so a request that omitted it fell through to a legacy batch path that wrote `VERIFIED_COMPLETE` and closed the location after requiring **only an authenticated actor** — and because `isDeptFloorActor` includes `associate`, the lowest-privilege actor in the product could verify the bay it had just reported. The branch was **deleted rather than re-gated**: it had zero runtime callers, barrier reporting already has its own actor-scoped owner, and `verify_all` already covers bulk close — the A1.10 precedent that **obscurity is not a control**. The supervisor gate now wraps the whole method, and because the acceptance law named *direct helper call* as a bypass, the verification loop inside the retained helper was removed too, leaving only a truthfully-named `stampDepartmentWeekVerified`. Second, `/api/rotations/complete` derived auto-verify from the **live session**, so an associate's offline completions flushing while a DS held the device silently became DS-verified. The queue persists no server-verifiable actor provenance and the payload's role string may not be trusted as authority, so the fail-closed rule was taken: **a replayed completion never auto-verifies**, even when the original actor genuinely was a DS. The marker enabling this can only *withhold* authority, never grant it. Verify and send-back also gained bounded state guards that read the **raw** column rather than the inferring resolver, so a pre-migration database still verifies correctly. **Live production schema was not confirmed** — no CLI, no config, no database tooling exists in the repo — so the repair was designed to be correct either way rather than resting on an assumed migration. Still deliberately open, each needing a product decision rather than a patch: **T-2** coverage debt (uncompleted bays are reset to `PENDING` and vanish from operational truth), **T-3** department scope on `/api/rotations/assign`, **T-4** the `sunday_bay_assignments.assigned_week` mismatch, and **T-6** destructive restaging defaults. **RUNTIME-COMPAT-001 (Production Runtime Contract Repair) — IMPLEMENTATION COMPLETE — AWAITING REVIEW** (2026-09-08), following the read-only **SCHEMA-RECONCILE-001** audit. Three operator-facing actions were broken against the live database in the same way — the code wrote columns production does not have — and all three were fixed **with zero schema change**, by moving the code onto production's actual shape. Barrier reporting targeted `bay_id` / `cycle_number` / `assigned_week` / `reported_by`; production's `rotation_exceptions` has `rotation_id` / `department_id` / `location_id` / `reason` / `logged_by`, so **every barrier report had failed and the table holds zero rows** — barriers had not disappeared from operational truth, they had never entered it. Production's hand-made shape proved the better normalization, because a barrier belongs to the rotation attempt it interrupted and week/cycle are reachable through `rotation_id`. Verify All verified the bays correctly and *then* threw on `departments.last_verified_week`, showing the supervisor a failure over genuinely verified work; **the stamp was deleted rather than migrated**, and department-week verification is now derived from the week's rotations through the existing `isRotationVerifiedComplete` predicate. Edit Bay Save wrote a nonexistent `store_locations.department_code` beside the valid `department_id`. Two readers had been hiding all of it — one reported a missing-column error as "no barriers this week", the other discarded its error and silently lost every associate name — and both now fail loudly against real columns, closing **THESIS-001 T-4**. Three fallbacks were removed because each had become the hazard it was written to prevent: two strip-and-retry paths that could close a location as `COMPLETED` with no verification evidence, and a hard `DELETE` that destroyed the rotation history superseding exists to keep. **THESIS-001A is intact.** Still deliberately open: **T-2** coverage debt, **T-3** department scope on `/api/rotations/assign`, **T-6** destructive restaging defaults, and the additive cycle-schema migration designed but not applied.
